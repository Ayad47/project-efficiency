## Project usage efficiency

Use the installed `project-efficiency` skill for knowledge setup, retrieval, and maintenance when useful. Reuse established context and inspect only task-relevant files. For indexed discovery, query the local cache; verify relevant source before edits. A known-file trivial edit can skip retrieval.

Prefer the smallest useful change. Preserve working behavior; avoid unrelated refactoring and speculative improvements. For complex work, identify scope, affected components, and risks once. Clarify material ambiguity before broad changes. Expand investigation only for a concrete need.

Run focused verification and required project checks; report what changed and what passed. Update affected knowledge after meaningful changes. Stale knowledge is a cache miss, never authority. Full inventories are for initialization, explicit reconciliation, or recovery—not every task.

Keep reasoning proportional to difficulty. Do not change user-selected models or spawn extra agents just to enforce this policy. Use `efficiency-steward` only for explicitly delegated knowledge work. This policy does not override current user instructions, repository requirements, or tool permissions.

Whenever Project Efficiency is used, announce it and include a brief final efficiency report: actual optimizations, measured elapsed time, and speed comparison. First setup also reports inventory and knowledge created. Show speedup only against a comparable measured baseline; otherwise state that it is not yet measurable. Do not manufacture savings or perform extra scans for reporting.
